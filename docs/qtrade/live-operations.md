# QMT、AI 自动监控与执行操作手册

本版本实现了官方 XtQuant 代码适配和执行工作流。**当前开发环境没有券商权限、SDK 和账户；没有完成券商侧连接、仿真或真实成交验收。** 软件测试中的假 SDK 不代表券商已接通。

## 从影子研究开始

启动后进入 `/qtrade/live`（侧栏“券商与 AI 执行”）。保存白名单、因子权重、入场/退出阈值和风险参数；后台任务与页面是否打开无关。默认模式为影子、AI 关闭、资金额度为 0。未连接券商时只生成研究审计；连接券商后可生成影子意图，但影子模式绝不报单或撤单。

多维输入复用 Qtrade / TSP 的标准研究上下文，仅对白名单内的完整样本排名。研究用日线因子，执行用 QMT 新鲜未复权盘口；这是“日线研究 + 盘中监控”，不是高频策略。单只股票在百分位样本中为 50 分，不能把此分数解读为盈利概率。默认最低成交额、缺值和 ST 过滤仍生效；数据不够就拒绝，不能切成演示数据。

启用 AI 后使用 TSP 已配置的低延迟 API 模型。每次输入只含数据日期、市场统计、因子权重和候选指标，不含资金账号、账户资产、券商路径或密码。输出必须是严格 JSON 风险意见：`allow / hold / reduce`、置信度、0–1 风险比例和理由。无工具调用、无代码执行、无订单字段。CLI 代理不用于这一实时复核。调用次数有每日硬预算，失败也计次，不进行隐式重试。

## 本机官方 SDK 配置

1. 向券商开通 QMT/MiniQMT 权限，获取券商认可的客户端和官方 XtQuant SDK，登录客户端。不要以屏幕点击脚本、网页抓包或 REA 绕过券商权限。
2. 选择与 SDK 匹配的 Python 版本。底座支持 Python 3.11+；若 SDK 仅支持不同 Python/系统环境，应先解决兼容性，不要把不匹配的二进制包强行放入运行环境。
3. 在本机进程环境设置 `QTRADE_QMT_USERDATA`（客户端真实 userdata 目录）、`QTRADE_QMT_ACCOUNT`（已登录的股票资金账号）。不在聊天、Git、截图或研究报告中填入密码/Token。平台不负责自动登录券商。
4. 在券商执行页点击“连接本机 QMT”。连接、订阅、资产、持仓、委托与成交查询必须完整成功。只有 SDK 文件存在不算已连接。

这些环境变量由启动进程读取。示意（用本机真实值替换占位，不要将文件提交 Git）：

```powershell
$env:QTRADE_QMT_USERDATA = '<本机券商客户端 userdata 目录>'
$env:QTRADE_QMT_ACCOUNT = '<本机已授权资金账号>'
.\start-qtrade.ps1 -SkipInstall -SkipBuild
```

QMT 文档将一些查询的 `None` 同时用于查询失败或空列表。平台按不确定处理，而不把它推断为空仓/无挂单；如果当前 SDK 在空账户上返回 `None`，接入验收将被阻止，需要在券商确认的 SDK 版本中解决该语义。没有“忽略错误继续下单”开关。

## 自动执行的开启条件

页面允许自由配置策略资金预算、单笔上限、单股与总敞口、日内亏损阈值、每日申报总额/次数、冷却、报价偏离、数据时效、止损和 AI 预算。0 额度仅是草稿，不能授权。

完成下面的券商仿真清单后，操作者可在本机声明 `QTRADE_BROKER_ACCEPTED=1`；准备开放真实券商写操作时再设置 `QTRADE_LIVE_ENABLED=1`。这些是部署者的显式声明，**不是系统独立证明券商已通过验收**。随后在页面核对配置并开启 1–60 分钟的限时自动授权。保存任何配置、断线、重启、异常或紧急停止都会撤销授权。

真实报单仍会重新读取账户、订单和原始报价，检查交易日、连续竞价时段、白名单、ST/停牌、有效涨跌停价、盘口、报价单位、偏离、T+1 可卖量、资金/仓位/亏损/申报额度、重复与冷却。只支持沪深主板普通股票的整手限价单；不支持融资融券、创业板、科创板、北交所、ETF、债券或期权。

不要共用执行工作区给不同资金账号。工作区按账户指纹绑定，切换账号需要独立 `DATA_DIR`。该策略账户应专用：外部委托或白名单外持仓会阻止自动执行。日内亏损是从本日首次成功读取的账户权益基线计算，重启不会重置；不是券商完整会计损益。外部出入金/分红等会影响该值，发生时暂停、核对并重新评估基线，不能把它当作已做现金流调整的收益。

同机同一资金账号还有独立的进程排他锁（系统临时目录下仅含账户指纹的 SQLite 锁文件），防止不同工作区同时建立自动执行连接。它不提供跨机器或跨操作系统账号的分布式排他；账户仍必须专用且仅由一个执行部署负责。

## 状态与恢复

- `planned`：持久化意图，尚未承诺报单。
- `submitting`：已持久化提交承诺。之后不允许同一幂等键再次提交。
- `accepted`：券商返回委托编号，**不等于成交**。
- `partial`：部分成交；未完成部分继续占用风险预算。资产与订单查询不是原子快照，平台对部分成交采取保守全额预占，可能多拒绝一些委托。
- `cancel_requested`：只发出了撤单请求；等待券商确认，不能提前释放占用。
- `filled / cancelled / rejected`：来自明确的券商状态或 SDK 明确 `-1` 拒绝。人工解除未知状态另有独立审计，不能混同券商证据。
- `unknown`：超时、重启时仍处于提交中、跨日未完成或未取得明确回报。撤销授权、禁止盲重发。先通过唯一的 24 字符备注和券商订单/成交对账。

若未知报单找到了正向回报，平台按证券、方向和数量一致性恢复状态，授权仍不恢复。若没有找到，空查询本身不足以证明未受理；页面提供“未知报单人工核对”，要求操作者核对券商当日及历史委托、成交、资金并记录至少 20 字的依据，明确声明未受理。该操作只是有审计的人工声明，保持暂停，不自动重发原意图。

紧急停止是持久化开关，立即阻止新的报单承诺；已进入本地 SDK/券商的请求不能被程序保证撤回。可以显式请求撤销本系统已有委托，但不能把请求成功当作撤单完成。保护性退出不等待 AI 或因子样本，但仍受价格、整手、T+1、单笔、冷却和申报额度约束，不保证在跳空、停牌、涨跌停或断线时按止损价成交。

## 券商仿真验收清单

1. 确认账户、运行环境、官方 SDK 版本、客户端版本、持仓/资金与原始价格单位。
2. 确认今日官方交易日历、证券状态、涨跌停、买卖盘口、最小报价单位和时间戳。
3. 在券商仿真环境验证单笔限价报单、拒单、部分成交、撤单请求与最终撤单回报；确认备注完整透传。
4. 将委托数量、累计成交、唯一成交号、持仓可用数量和资金与客户端逐一核对。确认空列表与查询失败的不同表现。
5. 验证报单前后断网、响应丢失、程序退出、重启对账、跨日未完成单、重复备注与 SDK 卡住。
6. 验证并发进程只允许一个执行者，修改配置/暂停/紧急停止后不产生新的提交承诺。SDK 同步调用卡住时工作进程可能仍需人工重启；系统保留提交记录和执行租约，不宣称能强行取消已进入 SDK 的请求。
7. 核对真实交易的程序化交易申报、券商协议、权限和适用规则。平台本次不替用户开通权限或办理这些手续。

## 本地控制面与审计

券商控制接口只允许回环 IP、受支持 Host 和同源浏览器请求，不进入公开 API Token/MCP scope。保留原 TSP 登录认证；推荐设置面板密码。默认启动脚本仅监听 `127.0.0.1`，不要把券商控制端口直接暴露公网。

本地 `data/user_data/extensions/qtrade_live/` 保存 SQLite 意图、审计、风险基线、AI 调用预算和券商成交回报副本；券商资产/成交仍是权威，不用该库推演另一套实盘资金账。数据库使用 WAL + FULL synchronous，唯一键在外部报单前提交。目录已被原 data 忽略规则排除。页面导出最近审计用于人工复核；不要公开包含个人交易的信息。

## 一手来源与策略边界

- [XtQuant 交易模块](https://dict.thinktrader.net/nativeApi/xttrader.html)：连接、订阅、查询、报撤单、状态与备注契约。
- [XtData 行情模块](https://dict.thinktrader.net/nativeApi/xtdata.html)：交易日、原始分笔、证券分类与价格限制字段。
- [AQR Value and Momentum Everywhere](https://www.aqr.com/Insights/Research/Journal-Article/Value-and-Momentum-Everywhere)：价值与动量的公开研究方法，启发多维而非单指标决策；本项目不是论文策略的逐式复现。
- [AQR A Century of Evidence on Trend-Following Investing](https://www.aqr.com/insights/research/journal-article/a-century-of-evidence-on-trend-following-investing)：趋势研究和长期验证的参考；不能外推本项目 A 股收益。
- [Microsoft Qlib](https://github.com/microsoft/qlib)：研究/训练/回测工作流参考；本轮没有引入其训练引擎或声称拥有机构私有模型。

公开论文不等于可立即盈利的 A 股策略。当前可交易的是透明的多维阈值规则、受约束 AI 风险复核与确定性执行；没有训练得到机构级 Alpha、行业中性化或经过真实历史样本外收益验收的声明。
