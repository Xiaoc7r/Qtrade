# 实盘与 AI 自动监控实施计划

## 已确认目标与验收边界

用户要求继续沿用 TSP，接入真实券商交易能力，按多个量化维度进行 AI 自动监控并在风控通过后自动交易，通过 GitHub PR 发布。用户确认目前尚未开通券商量化接口，因此这轮验收分为“可在本机完成的软件验收”和“需要券商环境的接入验收”。未填写资金及风险额度之前不能启用真实报单。

不存在能够承诺零错误或复制顶尖机构私有策略的系统。实现目标是：错误可检测、未知状态不重复下单、风险有硬边界、重启不静默恢复交易、订单以券商回报为准。

## 阶段与完成标准

| 阶段 | 实施内容 | 必须通过的验收 |
| --- | --- | --- |
| 1. 契约与研究 | 官方 QMT API、公开因子研究、状态机、威胁与故障模型 | 文档引用一手来源；不宣称获得机构私有策略 |
| 2. 券商适配 | 可选 XtQuant SDK：连接、账户/持仓/委托查询、原始行情、交易日历、限价报单与撤单 | 假 SDK 契约覆盖返回错误、空数据、断线、部分成交；缺 SDK 不影响 TSP 启动 |
| 3. 硬风控 | 额度、可用资金、仓位、日亏损、白名单、交易时段、T+1 可卖数量、行情新鲜度、价格限制、重复与频率 | 边界和拒绝用例；预占未完成委托；未知状态阻止新交易 |
| 4. 持久化执行 | SQLite 意图/审计、唯一幂等键、进程独占、提交前记录、券商对账、紧急停止 | 超时不盲重试，重启后恢复对账但不恢复授权；部分成交/撤单请求不当作最终完成 |
| 5. AI 监控 | 复用多维研究；受限结构化 AI 风险意见；周期任务；策略参数版本 | AI 只能否决或降低风险；无有效输出/超预算/过期均不交易；断开页面后后台仍可监控 |
| 6. 操作界面 | 配置、通道状态、监控、意图、风控拒绝、报撤单状态、暂停/紧急停止 | 加载/无 SDK/无账户/空数据/错误和桌面窄屏检查；不索要券商密码 |
| 7. 发布 | 回归、故障注入、变更审查、分支提交、PR、CI | 报告真实验证范围；用户可审阅 PR 后决定合并 |

## 系统边界

- 首个通道选择 QMT/MiniQMT 官方 XtQuant，按已登录的本机券商客户端连接。账户和 userdata 路径通过本机环境配置，不上传到 Git、不回传给 LLM。
- 首版自动交易只支持明确白名单内的沪深主板普通股票、整手、限价单、连续竞价。创业板、科创板、北交所、ETF、债券、融资融券不静默套用主板规则。
- 策略层复用标准行情与既有多维分析；市场环境、趋势、动量、量能、波动、估值分开说明。公开研究提供方法假设，A 股实际表现必须通过回测与仿真验证。
- AI 输出不拥有报单权限，也不能生成代码、修改资金上限、白名单或券商参数。确定性执行器拥有最终决定权。
- 真实资产和成交以券商为唯一权威；新增数据库是意图/审计/预占记录，不作为另一套券商账本。模拟盘保留原有 paper_execution。
- 影子模式可以生成研究记录，绝不调用报单/撤单。自动模式仍需用户填写风险额度、显式环境开关和当前进程的限时授权。
- 原始行情、交易日历、账户或订单查询不确定时停止报单；不使用演示数据、研究复权价或旧价格替代实时成交条件。

## 故障模型

| 故障 | 行为 |
| --- | --- |
| 报单网络超时/异常/进程退出 | 已写入的 submitting 意图视为未知，停止新报单；通过唯一备注查询正向回报，绝不自动重发 |
| 券商返回空委托/持仓的含义不确定 | 按未知处理，要求成功查询和环境验收；不把 None 当作已证明的空账户 |
| 下单后尚未记本地回执 | 重启按备注恢复；当前进程授权失效 |
| 部分成交 | 以券商累计成交数量/订单状态更新；剩余数量继续计入风险占用 |
| 撤单请求成功 | 仅记 cancel_requested；等待券商最终状态，不能提前释放风险额度 |
| AI 超时/非法 JSON/低置信度 | 记录拒绝，不退化为自动允许 |
| 多进程运行/暂停时仍在计算 | 独占执行租约；报单前重查授权、配置版本及停止标记 |
| 紧急停止 | 立即撤销进程授权，停止新交易；不盲目平仓或把未确认撤单当成功 |

## 必须留待券商环境完成

券商权限开通、匹配 SDK 与 Python 版本、客户端连接、真实交易日历与证券规则返回、委托备注透传、订单/成交查询完整性、券商仿真报撤单与重启对账。只有这些均有实际证据，才能标记“券商接入验收通过”。本轮不能用假 SDK 的测试通过替代该结论。
